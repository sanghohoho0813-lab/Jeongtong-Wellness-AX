# 회귀 점검 (qa/)

`npm test` 로 도는 vitest 는 **계산이 맞는지**를 본다.
여기 있는 것은 **실제 브라우저에서 눌리는지**를 본다.

두 가지는 자주 어긋난다. 점수 계산은 맞는데 단추가 안 눌리고,
값은 저장되는데 화면 숫자는 되돌아온다. 실제로 다음이 이 방식으로 잡혔다.

- 설정의 `기본 관리주기` 가 **아무리 쳐도 안 바뀌는 칸**이었다
  (값은 확정 설정에서 읽고 쓰기는 초안으로 했다)
- 숫자칸을 전부 지우면 옛 숫자로 되돌아가 다시 칠 수 없었다
- 긴 이름이 상태 배지를 화면 밖으로 밀어내 상태가 안 보였다
- 방문 기록 목록이 80건에서 **말없이 잘려** 나머지가 없는 것처럼 보였다
- 상담 내용을 한참 적다 창 바깥을 스치면 아무 말 없이 전부 사라졌다

## 돌리는 법

로그인 게이트가 켜져 있으면 직원 화면에 못 들어가므로, 점검용 서버는
데모 모드로 띄운다.

```bash
NEXT_PUBLIC_DEMO_MODE=1 npm run build
npx next start -p 4402 &

npm run qa
```

다른 주소를 보려면 `QA_BASE` 를 준다.

```bash
QA_BASE=https://<배포주소> npm run qa
```

## 준비물

Playwright 가 필요하다. 앱 자체는 쓰지 않으므로 `package.json` 에는
넣지 않았다 — 배포 빌드까지 무거워질 이유가 없다.

```bash
npm i -D playwright
npx playwright install chromium
```

이미 크로미움이 따로 있으면 경로를 준다.

```bash
QA_CHROMIUM=/path/to/chromium npm run qa
```

## 묶음

| 파일 | 무엇을 보는가 |
| --- | --- |
| `functional.mjs` | 매일 쓰는 흐름 — 고객 찾기 · 방문 기록 수정/삭제/되돌리기 · 이용권 · 관리 기준 미리보기 · 백업 · 글자 크기 · 새 고객 한 바퀴 |
| `mistakes.mjs` | 적다 만 것을 잃지 않는가 · 같은 사람을 두 번 등록하면 알려 주는가 |
| `keyboard.mjs` | 창이 열리면 초점이 창 안에 갇히는가 · ESC 로 닫히는가 · 닫으면 제자리로 · 입력칸에 이름이 붙어 있는가 |
| `layout.mjs` | 390px 폰에서 긴 이름 · 400자 메모 · 큰 글씨 · 어두운 화면을 한꺼번에 켜고 가로 넘침과 밖으로 나간 조각을 잰다 |
| `reach.mjs` | 누를 수 있는 크기인가(44×44) · 읽을 수 있는 대비인가(WCAG AA). 반투명 겹침을 실제로 합성해서 잰다 |
| `empty.mjs` | 고객 0명 — 실제 운영을 막 시작한 매장이 보는 화면. 깨진 값 · 막다른 길 · **하지 않은 일을 했다고 말하는 문장** |
| `bulk.mjs` | 고객 1,200명 · 방문 5,400건에서 각 화면이 4초 안에 그려지는가, 검색이 1초 안에 따라오는가 |

`empty.mjs` 와 `bulk.mjs` 는 브라우저 저장소를 갈아엎는다. 그래서 순서상
마지막에 돌린다 — 앞 묶음이 보던 자료를 건드리지 않기 위해서다.

## 판정 기준

**"있다" 로 통과시키지 않는다.** 화면에 단추가 보인다는 사실은 아무것도
증명하지 않는다. 글자 크기 '크게' 는 단추가 있는지가 아니라 누른 뒤
`body` 의 실제 글자 크기가 커졌는지로 본다.

## 개인정보

점검에 쓰는 이름·메모·전화번호는 전부 지어낸 값이다.
실제 매장 자료는 이 저장소에 넣지 않는다.
