# 실제 운영 시작하기 — 로그인과 권한

이 문서는 **한 번만** 하는 설정이다. 순서대로 하면 된다.

---

## 0. 지금 어떤 상태인가

앱은 두 모드로 돈다.

| | 로그인 | 화면에 있는 자료 | 직원 전환 |
|---|---|---|---|
| **체험 (Demo)** | 없이 들어감 | 이 기기 안 가상 자료 | 가능 |
| **실제 운영** | 반드시 로그인 | 서버(Supabase) 자료 | 불가 — 서버가 정한 계정 하나 |

가르는 것은 환경변수 하나다.

```
NEXT_PUBLIC_DEMO_MODE=1   ← 체험 모드
(변수 없음)                ← 실제 운영  ★ 기본값
```

변수를 깜빡하면 **잠기는 쪽**으로 간다. 잊었을 때 열려 버리는 쪽으로
기울면 그 순간이 곧 사고이기 때문이다.

---

## 1. SQL 세 개를 순서대로 실행한다

Supabase 대시보드 → SQL Editor 에서, **위에서부터 차례로**.

| 순서 | 파일 | 하는 일 |
|---|---|---|
| 1 | `supabase/schema.sql` | 매장 자료 표 · RLS · 권한 |
| 2 | `supabase/portal.sql` | 고객 포털 표 · RLS · 연결코드 |
| 3 | `supabase/auth-hardening.sql` | **연락처 잠그기 · 직원 계정 잇기 함수** |

3번은 이번에 새로 생긴 것이다. 실행하면 화면 아래에 확인 결과가 나온다.
**네 줄이 모두 PASS 여야 한다.**

```
t1_하이픈_번호_가림          PASS   010-****-5678
t2_붙여쓴_번호_가림          PASS   010-****-5678
t3_모르는_모양은_통째로_가림  PASS   ***-****-****
t4_연락처_컬럼_읽기_차단      PASS
```

> **3번을 실행하기 전에는** 직원이 API 로 고객 연락처 원문을 받을 수 있다.
> 화면에서는 가려 보이지만 그건 화면일 뿐이다. 실제 고객자료를 넣기 전에
> 반드시 실행한다.

---

## 2. 관리자 계정을 만든다

1. Supabase 대시보드 → **Authentication → Users → Add user**
   (또는 Invite user) 로 원장님 이메일 계정을 만든다.
2. 앱에 그 계정으로 로그인한다 → “직원으로 등록되지 않은 계정입니다” 가 뜬다.
3. SQL Editor 에서 그 계정을 직원 레코드에 잇는다.

```sql
update staff
   set auth_user_id = (select id from auth.users where email = '원장님@이메일')
 where name = '원장님 이름' and role in ('owner','manager');
```

한 번만 이렇게 하면, 그다음부터는 앱 안에서 할 수 있다(3번).

---

## 3. 직원 계정을 늘린다 — 앱 안에서

1. Supabase 대시보드에서 그 직원의 이메일로 계정을 만든다(초대).
2. 관리자로 로그인 → **설정 → 직원 → 계정 연결** 에 그 이메일을 넣는다.
3. 같은 줄에서 역할(대표/관리자/직원)을 고른다. 이게 곧 권한이다.

계정 생성만 대시보드에서 하는 이유는, 사용자를 만들려면
`service_role` 키가 필요한데 그 키를 브라우저에 두지 않기 때문이다.

퇴사·기기 분실 시에는 같은 자리에서 **연결 해제**를 누른다. 즉시 끊긴다.

---

## 4. 고객 계정 — 연결코드로

고객은 스스로 가입하지 않는다. 매장이 건네는 여섯 자리 코드로 **잇기만** 한다.

1. 고객 상세 → **연결코드 발급** → **안내문 인쇄** 로 종이를 드린다.
2. 고객이 `/my` 에서 이메일로 숫자 여섯 자리를 받아 로그인한다.
3. 그 화면에서 연결코드를 한 번 넣으면 끝난다.

코드는 1회용이고 만료일이 있다. 코드를 가진 사람만 그 고객의 기록에 닿는다.

---

## 5. 확인 — 이렇게 되면 제대로 된 것이다

- 로그인하지 않고 `/customers` 를 치면 `/login` 으로 간다
- 직원(staff) 계정으로 `/settings` 를 치면 `/customers` 로 되돌아온다
- 직원 화면에서 고객 연락처가 `010-****-5678` 로 보인다
- 관리자 화면에서는 원문이 보인다
- 고객 A 로 로그인해 다른 고객 번호를 주소창에 넣어도 아무것도 안 나온다
- 사이드바에 ‘전환’ 이 없고 ‘내 계정’ 만 있다

---

## 6. 시연용 주소를 따로 둘 때

Vercel 에서 미리보기(preview) 배포에만
`NEXT_PUBLIC_DEMO_MODE=1` 을 넣으면, 그 주소는 로그인 없이 가상 자료로
돈다. 실제 고객자료는 서버에 있고 서버는 로그인해야 열리므로, 시연 주소로
실제 개인정보에 닿을 길이 없다.

운영 주소(Production)에는 **절대 넣지 않는다.**
